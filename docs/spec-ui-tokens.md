# UI token 规范 · ElecKoi Tavern

> 这份文件回答一个问题：**改界面时，哪些值该写成变量，哪些不该。**
> 它不是为了"统一而统一"——是因为**同一个值被写死 40 次之后，改一次要改 40 处，还会漏。**

统计时间：2026-09-27（`ui/assets/characters.css`，3036 行）

---

## 一、现在的家底

`:root` 里已经有 **29 个 token**，质量和覆盖率都不错：

| 组 | token | 使用次数 |
|---|---|---|
| 纸底 | `--bg` `--bg-warm` `--surface` `--surface-2` | 2 / 3 / 18 / 23 |
| 描边 | `--border` `--border-strong` | 68 / 9 |
| 墨色 | `--fg` `--fg-dim` `--fg-muted` | 34 / 18 / **91** |
| 强调 | `--accent` `--accent-2` `--accent-soft` `--accent-line` `--accent-glow` | 57 / 5 / 13 / 23 / 5 |
| 语义 | `--danger` `--danger-soft` `--success` | 10 / 2 / 4 |
| 圆角 | `--r-sm` `--r-md` `--r-lg` | 12 / 11 / 6 |
| 动效 | `--ease` `--t-fast` `--t` `--t-slow` | **72** / 3 / **63** / 5 |
| 阴影 | `--sh-1` `--sh-2` `--sh-3` | 8 / 2 / 2 |

**两个值得说的地方：**

1. **底色接了宿主** —— `--bg: var(--hana-bg, #fdf8ec)`。这是对的：宿主给什么底色就跟什么，拿不到才用自家暖纸。**这一条不要动。**
2. **颜色已经收得七七八八**。硬编码 hex 只剩 49 处，其中一半还是 `#fff` 和那几个"天上掉下来的"颜色（见第四节）。

**所以真正失控的不是颜色，是字号和间距。**

## 二、字号：15 种 → 6 档

这是全仓最乱的地方。166 处 `font-size`，用了 **15 种不同的值**，其中 **7 种是半像素**：

```
20(2) · 16(2) · 15.5(1) · 15(3) · 14.5(2) · 14(5) · 13.5(3)
· 13(25) · 12.5(19) · 12(40) · 11.5(19) · 11(31) · 10.5(10) · 10(3) · 9.5(1)
```

**半像素是怎么来的**：不同时间、不同的人，为了让某处"再小一点点"随手写了个 `.5`。
19 次、19 次、10 次——这些已经是**事实上的档位**了，不能当脏数据清掉。

**收口做法：不删档，把在用的命名，把一次性的归并。**

```css
/* 字号：按使用频次定型，不是按"应该有几档" */
--fs-2xs:  10.5px;   /* 小标签、徽章 */
--fs-xs:   11.5px;   /* 次要文字、备注 */
--fs-sm:   12.5px;   /* 正文（最常用） */
--fs-md:   13px;     /* 小标题、列表项名 */
--fs-lg:   15px;     /* 区块标题 */
--fs-xl:   20px;     /* 大标题、空态主句 */
```

**归并表**：

| 原值 | 出现 | 去处 |
|---|---|---|
| 9.5px | 1 | `--fs-2xs` |
| 10px | 3 | `--fs-2xs` |
| 10.5px | 10 | `--fs-2xs` ✓ |
| 11px | 31 | `--fs-xs` |
| 11.5px | 19 | `--fs-xs` ✓ |
| 12px | 40 | `--fs-sm` |
| 12.5px | 19 | `--fs-sm` ✓ |
| 13px | 25 | `--fs-md` ✓ |
| 13.5px | 3 | `--fs-md` |
| 14px | 5 | `--fs-lg`（或 `--fs-md`，视上下文） |
| 14.5px | 2 | `--fs-lg` |
| 15px | 3 | `--fs-lg` ✓ |
| 15.5px | 1 | `--fs-lg` |
| 16px | 2 | `--fs-lg` |
| 20px | 2 | `--fs-xl` ✓ |

**注意**：`11px(31)` 和 `12px(40)` 是使用最多的两个，但它们**没有对应的档**（档给了 11.5 / 12.5）。
落地时二选一：**要么把 11/12 也设成档，要么把它们归到 11.5/12.5**。
**建议前者**——31 处和 40 处的改动量，比"视觉上差 0.5px"重要。

## 三、间距：12–14 种 → 9 档

```
gap:     8(25) · 6(20) · 4(9) · 10(9) · 5(4) · 14(4) · 12(3) · 1(2) · 3(2) · 7(2) · 11(2) · 15(1)
padding: 12(15) · 10(12) · 1(10) · 8(10) · 3(9) · 14(7) · 9(6) · 2(5) · 4(5) · 6(5) · 11(4) · 5(3) · 7(2) · 15(2)
```

**已经有了一个事实上的节奏**：2 / 3 / 4 / 5 / 6 / 8 / 10 / 12 / 14。
奇数居多（3 / 5 / 7 / 9 / 11）说明有人是按"感觉差一点"调的。

```css
/* 间距：4px 基准 + 2px 微调档。奇数档保留——它们已经在用了 */
--sp-1:  2px;
--sp-2:  3px;
--sp-3:  4px;
--sp-4:  5px;
--sp-5:  6px;
--sp-6:  8px;
--sp-7:  10px;
--sp-8:  12px;
--sp-9:  14px;
```

**不做的两件事**：

1. **不把 7/9/11/15 强行并掉**。它们各只出现 2–6 次，但都在**具体位置上有理由**（比如一条 1px 边框配 7px padding 刚好对齐）。并掉是"视觉改动"，不是"收口"。
2. **不把 `1px` 收成 `--sp`**。`1px` 出现 98 次，**绝大多数是 border**（62 次 `border` + 11 `border-bottom` + 7 `border-top`）。
   它是**描边宽度**，不是间距——见下一节。

## 四、圆角：9 种 → 5 档

```
999px(16) · 8px(11) · 10px(9) · 6px(7) · 5px(3) · 3px(1) · 4px(1) · 7px(1) · 9px(1)
```

**已有 `--r-sm: 8px` / `--r-md: 12px` / `--r-lg: 14px`，但 10px / 6px 这两个高频档没有对应的 token。**

```css
--r-xs:   6px;     /* 小控件：徽章、勾选槽 */
--r-sm:   8px;     /* 已有 —— 常规控件 */
--r-md:   10px;    /* 新增 —— 卡片、面板（原来这个位置被写死 9 次） */
--r-lg:   14px;    /* 已有 —— 弹窗、抽屉 */
--r-pill: 999px;   /* 胶囊：当前写了 16 次 */
```

**归并**：`3/4/5px` → `--r-xs`；`7/9px` → `--r-sm`；**`12px` 保留在 `--r-lg` 之外单独看**（它用了 11 次，但值本身介于 md 和 lg 之间，落地时按上下文选）。

> ⚠️ **`--r-md` 的语义变了**。原来是 `12px`，现在建议改成 `10px`。
> 落地前先 grep `var(--r-md)` 的 11 处，确认它们都能接受 10px——**不能接受的就留在 `--r-lg`**。

## 五、颜色：只补四处

49 处硬编码 hex 里，真正需要处理的：

| 值 | 出现 | 是什么 | 去处 |
|---|---|---|---|
| `#fff` | 7 | 强调底色上的字 | `--on-accent` |
| `#7dd3fc` | 6 | 消息类型色（青） | `--type-*` |
| `#f87171` | 4 | 消息类型色（红） | `--type-*` |
| `#fbbf24` | 2 | 消息类型色（黄） | `--type-*` |
| `#fffdf7` | 5 | 就是 `--surface` | 直接用 token |
| `#fdf8ec` | 4 | 就是 `--bg` | 直接用 token |

**那几个青/红/黄是"天上掉下来的"**——它们的色相和暖纸底整体不搭（暖纸是橙褐系，这三个是冷色）。
它们目前用在消息类型标记上（旁白/系统/插图之类）。**不要急着改色**，先收成 token：

```css
--on-accent: #fff;              /* 强调底上的字 —— 只有这个场合用白 */
--type-narration: ...;          /* 落定色再填 */
--type-system:    ...;
--type-illustration: ...;
```

**底色和描边已经有 token 了**（`--bg` / `--surface` / `--border`），第 5、6 行那 9 处是**漏网**，直接换掉即可。

## 六、什么不该收成 token

**这一节和上面同样重要。**

| 不该收的 | 为什么 |
|---|---|
| `width: 344px`（抽屉宽） | **一次性的布局常量**。它只出现一次，收了也只是换个名字，还多一层跳转。 |
| `height: 100%` / `width: 100%` | 不是尺寸，是"填满"。 |
| 单次出现的 `font-size: 15.5px` | 归并到档位（见第二节），**不是新开一个 token**。 |
| `gap: 7px` 这种 2 次的值 | 它的存在有具体理由，收 token 只是变相把它"合法化"。 |
| `transition: all .15s` 里的 `.15s` | 动效时长已有 `--t-fast` / `--t` / `--t-slow`；**先把这三档用满**，别再加第四档。 |

**判断标准一句话**：

> **同一个值，在三个以上地方出现、且改了要一起变** → 收成 token。
> **只在一处出现、或者各处的"恰好合适"互不相同** → 留着。

## 七、落地顺序

1. **先补 token**（字号 6 + 间距 9 + 圆角 2 + 颜色 1），**不动任何现有规则**
   —— 这一步零风险，加完全都是新增行。
2. **再按组替换**：字号 → 间距 → 圆角 → 颜色；**每组替换完跑一次全量测试 + 目视检查**
3. **最后删掉 `--r-md` 的语义冲突**（先 grep 那 11 处确认）

**不要一次全改。** 643 处 px 里大部分是 `border: 1px`（98 处）——那些**本来就不该动**，
真正要替换的是 **gap / padding / font-size / border-radius 四类，约 260 处**。

## 八、一条今天学到的纪律

**九个「刷新」按钮。**

七个抽屉 + 宿主左栏 + 预览弹窗，每个都有一个 `refresh-*-btn`，
全都绑到 `load*`——而打开抽屉、增删改之后本来就会自动重载。**它们一次都没有被按过。**

这不是设计问题，是**复制问题**：第一个抽屉这么写了，后面七个照抄。
**所以规范里要有一条**：

> **新加一个控件之前，先问它有没有可能"从来不需要被按"。**
> 特别是那些名字里带"刷新 / 重载 / 更新"的——它们多数是"我以为需要"。

同类的还有：**「关闭」和 ✕ 并存**（`#bg-modal` 里三个按钮全是"关"）、
**两个都叫"导出"的按钮**（`#modal` 页脚的 JSON 和 ST）。
它们都是**同一个动作被写了两遍**。
