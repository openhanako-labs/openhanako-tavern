## 四、S1 状态栏 2.0 · 交互稿（奥菲莉娅定稿，09-29 晚）

**地基核实结论**（比 v1 想的还近一步）：`diffVars` 本来就会产出 `change: "add", from: null`，
服务端把每条 diff 连显示文本（`text`）一起拼好随消息下发，前端 var-chip 只负责印。
所以 S1 实际是**一个面板 + 一处文案微调**，不动账的算法。

### 1. 文案：`describeVarDiff` 微调（lib/variables/diff.js）
- `add`（首次出现）：`名称 空 → 值`（对齐 AIRP 的「容貌：空→80」）
- `set` 且 `from === ""`（空串补齐）：同样按 `空 → 值` 显示
- 其余分支不动。**红线不动**：账从状态长出来、值按字符串比。

### 2. 面板：「本轮发生了什么」
- **入口**：chips 行末尾加一颗小按钮「明细 ›」（行内一颗，不每条一个）；
   chips 行本身保留作速览，不删。
- **形态**：modal（复用 Q3 瑞贝卡加的 `#models-modal` 同一套模态件，别另造）。
- **内容**：当前这条 assistant 消息的 `varDiff`，按 `add / set / remove` 分三组，
  逐条整行：`变量名  空 → 值`，**不截断**（chips 里截断的 24 字限制只留给 chips）。
  组头显示条数，如「新增 3 · 变更 2 · 移除 1」。
- **修改**：面板右上角「修改本轮变量」按钮 → 打开既有的变量抽屉
  （`variables/routes.js` 的编辑链路已存在，跳过去即可，不在 modal 里内嵌编辑器——
  一处编辑入口，不养双胞胎）。
- **空态**：这轮没有变量变化时不显示「明细 ›」按钮（chips 行本来就不出现）。

## 四.5、S2 记忆面板 · 向量评估（已核实，不接）

**结论：只写评估，不接开关。** 理由：`lib/embed/` 现状只有 `embed()`（算向量）与 `status()`（体检），
没有「把向量存下来」也没有「按余弦/内积捞旧消息」这条路。加个「向量记忆」开关只能做成「关与开都一样」
——两条路都在走当前纯滑动窗口，等于白接一根假线。开关的诚实意义在于「关了走现状、开了走另一条路」，
两条路一样时开关就是自欺。

**接入需要的三块（等 C 线数据模型一页纸时可一并设计）：**
1. 存储层：向量表（`<dataDir>/vectors/*.json` 或 sqlite），字段 `msgId / convId / embedding / model / dim`
2. 写时钩子：消息落盘后异步算向量写入（不阻塞回复）
3. 读时钩子：发正文前，用当前用户输入的向量捞 top-K 旧消息，作为上下文尾巴拼进 prompt

**现在埋的伏笔（不接开关的部分）：**
- `lib/memory/config.js` 里预留了 `summaryPrompt` / `summaryMaxChars` / `keepRecent` 三格——
  将来接向量时可以在同一份 config 里加一格 `vectorMemory`，不必再改文件路径与路由。
- 记忆面板里有一节「向量记忆（未接入）」，只读展示当前 `embed` 状态，
  并在 hint 里明说「不接的理由」。将来接入时改这一节，不必新增面板。

### 3. 验收
- 一轮里新出现的变量显示 `空 → 值`；改值显示 `旧 → 新`；移除显示原文案。
- 点「明细 ›」出面板，三组分类正确，长值完整可见。
- 「修改本轮变量」能跳到变量抽屉并真的改成功。
- chips 速览行渲染与之前一致（不回归）。
