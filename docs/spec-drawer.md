## 零、这份文件管什么

ElecKoi 有**八个抽屉**：设定库 + 角色 / 变量 / 公式 / 预设 / 正则 / 工具 / 迁移。

其中**七个**（除设定库）的骨架其实已经统一了：

```
.drawer
  ├─ .drawer-head       标题 + 关闭
  ├─ .drawer-toolbar    这一页的主操作
  └─ .drawer-body       列表 / 表单
```

**结构是对的，不该重造。** 问题在于它们各自长出来的细节不统一——
设定库在基准 4 里刚立的那套（计数单独一行、搜索行、控制行、分页吸底、三态分开）没跟过去。

所以这份规范做两件事：

1. **把设定库那套搬过来**，定成七个抽屉共同遵守的骨架
2. **修掉四处共有的毛病**（见第三节）

## 一、骨架：七段，按需取用

```
① .drawer-head      标题 + 关闭        必选
② .drawer-toolbar   本页主操作         可选（没有动作就不放）
③ 计数行            单独一行           可选
④ .drawer-filter    搜索 / 分组 / 排序  可选（只有列表类且有量才放）
⑤ .drawer-body      列表 / 表单         必选
⑥ 分页             吸底               可选（不足一页不显示）
```

### ① 头 `.drawer-head`

标题 + 关闭。**不动。**

### ② 工具条 `.drawer-toolbar`

**只放这一页的主操作**，一颗实色（`btn-primary`）打头，其余 `btn-ghost` / `btn-sm`。
零散动作收进 `⋯`（复用 `.more-toggle` + `.more-menu`）。

**纪律：新加一个控件之前，先问它有没有可能"从来不需要被按"。**

> 这一条是踩出来的：曾经七个抽屉 + 宿主左栏 + 预览弹窗，每个都挂一颗
> `refresh-*-btn`，全绑到 `load*`——而打开抽屉、增删改之后本来就会自动重载。
> **它们一次都没有被按过。** 这不是设计问题，是复制问题：第一个这么写了，
> 后面八个照抄。

### ③ 计数行

**单独一行，不挤在工具条里。** 挤进去会把 344px 的工具条折成三行。

```html
<div id="settings-count" class="drawer-count"></div>
```

- 空的时候 `:empty { display: none }`，不留空带
- **工具条是动作位，计数是状态——两块东西不能混**

### ④ 筛选行 `.drawer-filter`

搜索框吃满一整行，两个 select 平分下一行（344px 装不下三者并排）。

**只有"条目多得需要组织"的抽屉才放。** 变量抽屉十几条，不需要。

### ⑤ 列表 `.drawer-body`

条目 + 分组抬头，抬头可折叠（见下）。

### ⑥ 分页

吸底。**条数少于一页的不显示这一行**——不是"显示 1/1"，是整行不出现。

## 二、分组抬头

```html
<div class="section-head" data-key="0" data-act="toggle-fold">
  <span class="section-arrow">▾</span>
  <span class="section-title">常驻</span>
  <span class="section-hint">每轮都在上下文里</span>
  <span class="section-n">64</span>
</div>
```

三条硬要求：

1. **`position: sticky; top: 0`** —— 106 条要滚很久，滚到第 40 条时还得知道自己在哪一组
2. **`z-index` 要压得住卡片** —— 卡片从抬头头顶的 padding 带里透出来过（见下）
3. **`data-key` 必须能对上折叠状态的读写两端** —— 见下

### 坑一：sticky 只粘到「内边距盒」的顶边

`.drawer-body` 有 `padding: 12px 16px`，而 sticky 只粘到**内容边缘**——
上方那 12px 的 padding 带不在抬头的覆盖范围内，卡片会从那一条里穿过去。

**修法**：容器顶部不留内边距，纵向内边距改由各段自己承担。

```css
#settings-list { padding: 0 16px 12px; }
#settings-list > .setting-section:first-child { padding-top: 12px; }
```

顶部呼吸感回到第一个分组身上——**它随内容滚动，不会形成泄漏带**。

### 坑二：`data-key` 与折叠 key 的读写两端

分组 key 可能是**数字**（`SETTING_SECTIONS` 就是 `0/1/2`），
而 `dataset` 读回来永远是**字符串**。

两端不统一，表现是**「点了没反应」**：不报错、不抛异常，只是永远读回 false。

> 真事故（2026-09-28）：
> `renderSection` 写 `data-key="${escapeHtml(g.key)}"`，
> 而 `escapeHtml` 当时用 `!str` 判空 —— `!0` 为 true，
> 于是 `escapeHtml(0)` 返回空串，常驻组抬头变成 `data-key=""`。
> 点击写 `...:trigger:`，渲染读 `...:trigger:0`，两端永远错位。
> 而「触发」「已停用」的 key 是 1/2，恰好能对上 —— 所以**只有常驻坏**。

**修法（两层，都要）**：

1. `escapeHtml` 的守卫改成 `str == null || str === ""`，不再用 `!str`
2. 折叠 key 的构造收成唯一入口 `settings-fold.js` 的 `foldKey(dim, key)`，内部 `String()` 化

**测试**：`test/regression-settings-fold.mjs` + `test/check-escape-html.mjs`

## 三、四处共有的毛病（一起修）

### 毛病 1：「刷新」按钮

**七个抽屉全有，一次都没被按过。**（原因见 ②）

**做法**：拿掉。改成数据变了自己重画。
真需要外部重载的（导入之后）留一个「重新加载」在**计数行末尾**，不是工具条里。

### 毛病 2：计数挤在工具条里

设定库已经挪出来了，其余跟着挪（见 ③）。

### 毛病 3：加载态和空态混用

七个抽屉的空容器都写着 `<div class="empty">加载中…</div>`。
**数据回来了但确实没有，也说"加载中"，用户会一直等。**

必须分开成三态（见第四节）。

### 毛病 4：工具抽屉的工具条夹在中间

它原来的顺序是「App 设置面板 / 工具条 / 工具列表 / 工具组」——
工具条该在最上面，和其他抽屉一致。**已修。**

## 四、三态：加载 / 空 / 错

三态要分开，**因为它们的"下一步"不一样**。

| 态 | 用户该做什么 | 给什么 |
|---|---|---|
| **加载中** | 什么都别做，等一下 | **骨架条**，不是转圈 |
| **空** | 这里确实什么都没有，而且多半是因为你还没建 | 一句解释 + 一个动作按钮 |
| **错误** | 出事了，而且要先分清是**谁**出的事 | 错误标题 + 原因 + 重试 |

### 为什么加载态用骨架条不用转圈

转圈只说明"我在忙"；骨架条还告诉你"**将要出现的是两条带副标题的东西**"。

### 空态是第一次打开时唯一的说明书

所以文案要写"**这个功能是干什么的**"，不是"暂无数据"。

### 三条文案纪律

1. 不说"暂无数据"——说**没有的是什么**（"还没有正则规则"）
2. 不说"操作失败"——说**失败在哪一步、为什么**，能贴错误码就贴
3. 空态那句话要能**教一次用法**（正则那个空态就顺手说了"建了记得试一下"）

### 公共类

```html
<!-- 加载：骨架条 -->
<div class="d-skel">
  <div class="d-skel-bar w46"></div>
  <div class="d-skel-bar w82"></div>
  <div class="d-skel-bar w64"></div>
</div>

<!-- 空：图标 / 标题 / 解释 / 动作 -->
<div class="d-state">
  <div class="d-state-ico">⌗</div>
  <div class="d-state-title">还没有正则规则</div>
  <div class="d-state-desc">规则是对文本做的替换。…</div>
  <button class="d-state-go">+ 新建一条</button>
</div>

<!-- 错：标题 / 原因 -->
<div class="d-err">
  <b>没能读到设定库</b>
  连接宿主 App 服务失败（ECONNREFUSED 127.0.0.1:8787）。这不是你的数据出了问题。
</div>
```

**命名说明**：旧代码里已有 `.preset-skel` / `.preset-empty` / `.preset-err`
（预设抽屉是最早做对的），本规范把它们提升为公共类 `d-` 前缀。
预设抽屉保留旧类名作兜底，新代码一律用公共类。

## 五、列表项五型

**四种基本型覆盖九成条目。** 不做更多花样——七个抽屉加起来几十种条目，
每多一种型就多一份要对齐的东西。

| 型 | 形态 | 什么时候用 |
|---|---|---|
| **甲** | 单行 + 开关 | 开关是唯一动作（变量、角色） |
| **乙** | 名字 + 一行摘要 | 有条"一眼认得出来"的关键信息（预设的 temperature、正则的表达式） |
| **丙** | 带徽章行 | 需要标明"这条属于谁 / 作用在哪" |
| **丁** | 可展开看正文 | 正文长、但只是偶尔要看 |

### 两条硬纪律

1. **徽章只在变化时才画**（设定库那条规矩）
2. **操作永远 hover 才出** —— 一个抽屉里几十条，每条挂两个按钮就是墙纸

## 六、验收清单

新加或改一个抽屉时，对着走一遍：

- [ ] 头 + 工具条 + body 三段齐全
- [ ] 工具条里没有"从来不需要被按"的控件
- [ ] 计数单独一行，不在工具条里
- [ ] 计数为空时不留空带
- [ ] 加载态是骨架条，不是"加载中…"
- [ ] 空态写了"没有的是什么" + 一个动作
- [ ] 错误态说清了是谁的错
- [ ] 列表项落在四型之内
- [ ] 操作 hover 才出
- [ ] 分组抬头 sticky，且不从 padding 带泄漏
- [ ] 分页不足一页时整行不显示
